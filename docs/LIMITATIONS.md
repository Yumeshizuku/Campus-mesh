## 系统边界

- iOS 进入后台时停止 BLE 与 TCP，回到前台恢复身份、缓存及手动邻居。没有伪装后台模式或持续运行保证。后台收不到的新消息，无法触发离线通知；前台收到后可记录并申请本地通知。
- Android 采用用户可停止的 connectedDevice 前台服务及本地通知，系统蓝牙/附近设备/定位权限和厂商省电策略仍会影响工作。未持有持续 CPU 唤醒锁；Doze/熄屏下交付必须按机型测量。
- Android Wi-Fi Direct 仅在支持的 Android 设备间可用，系统决定群主、配对许可和拓扑；不能保证与普通 Wi-Fi 同时保持，也不能保证同时跨两个 P2P 群中继。iOS 没有等价的通用公共接口。
- iOS 默认使用 BLE 自动发现；TCP 用手动 IPv4 地址。UDP 广播必须先获得适用权限/entitlement 后才能在 iOS 开启；普通发布构建不请求该特殊权限。
- BLE 广播、扫描、并发连接数量、最低 MTU 写入节奏均受硬件和系统影响。接入代码尚未真机验证；短包、中文、长包、断线途中重新分片及双角色兼容性是待验收项。无 MTU 提速、BLE inventory 或传输队列超时重建策略。
- 5 秒同步是空闲时的目标周期；串行邻居拨号、慢连接和磁盘容量会拉长它。缓存与已见表只按条数有界；大文本占用内存和电量仍显著。全量 JSON 历史轮询不是最终数据库/分页架构。
- 手机时间需大致一致：未来超过 5 分钟的封装会被拒绝，24 小时有效期依赖本地时间；没有无网络安全授时。
- TTL 到期标为 `expired`，并不代表收件人一定未收到；ACK 也可能丢失或尚未返回。
- 明文聊天记录和长期私钥存于应用沙盒状态文件，非独立加密数据库或硬件密钥存储。Android 禁用备份；iOS 目录排除备份并设置文件保护。生产版本需要 Keystore/Keychain 与密钥迁移方案。
- 只隐藏消息内容，不隐藏公钥、收件人、时序、包长或拓扑。无前向保密、匿名通信、已认证会话握手、准入控制或完善洪泛防护；见架构文档。

学校白板不得安装软件、不得绕过权限或网络限制。若校园网络隔离客户端，使用自己的热点/蓝牙或取得网络管理员授权；不能用本项目绕过隔离。Windows 模块完全可选。

## 完成最终验收还需

macOS + Xcode、至少两台 Android 和一台 iPhone，完整的四设备三跳最好使用四台手机；之后再开展不同品牌、熄屏与恢复、10–300 节点负载/丢包/功耗实验。必须根据真实结果修复原生链路，再讨论容量和稳定性目标。当前环境无连接手机、无 macOS，不能完成这些步骤。
