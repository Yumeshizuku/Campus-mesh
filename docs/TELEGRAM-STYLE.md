# 0.3 Telegram 风格界面更新

0.3 版本采用了更接近 Telegram 的聊天布局：先在列表中找到会话，再进入独立聊天页。应用仍使用 Campus Mesh 的名称和公钥身份，原有的通信功能与自定义设置也都保留。

## 界面有哪些变化

- 新安装默认使用蓝色主题。Android 增加了蓝色工具栏和抽屉导航入口，iOS 使用简洁的原生导航栏。已经设置过的主题色、字号和深浅色偏好会继续生效。
- 会话列表会显示圆形首字头像、最近一条消息、时间、未读数量和草稿提示，常用会话优先排列。还没有联系人时，会显示空列表提示。
- Android 可以按“全部 / 私聊 / 群发”筛选会话，也可以通过右下角按钮新建会话。点开会话进入聊天页，返回后回到列表。
- 进入聊天页后，底部页签会收起，顶部显示头像和名称。会话搜索与设置放在顶部菜单中。
- 默认蓝色主题在浅色模式下使用白色接收气泡、浅绿色发送气泡和淡灰绿色背景；深色模式则使用深蓝色背景与气泡。选择其他主题色时，浅色模式中的气泡会使用相应的主题色。
- 消息改为带方向的圆角气泡，日期、时间和发送状态也重新排布。发送按钮采用圆形纸飞机图标，快捷短语可以从输入区菜单中选择。
- 外观自定义、草稿保存、常用群发和部分提交失败后的重试功能都可以继续使用。头像颜色根据身份或会话 key 稳定生成，头像本身使用首字，而非用户照片。

## 未读和送达状态是什么意思

未读数字表示这台设备上尚未查看的消息。进入会话后，已有消息会标记为已查看；这些记录保存在本机偏好中，不会向对方发送新的“已读”回执。

“✓ 已送达”表示通信核心已经验证了端到端 ACK。“等待送达”和“已过期”同样根据核心返回的实际状态显示。这个版本没有加入在线时间、通话、文件附件或云同步功能。

## 这个版本完成了哪些检查

Android 0.3.0 / versionCode 3 已完成 ARM64 APK 构建和 Lint 检查，结果为 0 errors / 9 warnings，未屏蔽错误。详细记录见 `reports/telegram-android-build.txt` 和 `reports/telegram-android-lint.txt`；APK 签名与 16 KB 对齐检查分别记录在 `reports/telegram-apk-signature.txt`、`reports/telegram-apk-alignment.txt`。

在这个版本的验证阶段，iOS 的七个 Swift 文件通过了语法解析，记录见 `reports/telegram-swift-syntax.txt`。当时尚未进行 Swift 类型检查或 Xcode 完整构建，后续的 macOS/Xcode 构建进展见 [验证报告](VERIFICATION.md)。

0.3 版本没有完成模拟器或真机上的交互检查，也没有实际运行截图。此前搭建的软件模拟器未能完成冷启动，因此仍需换到能正常启动的专用模拟器上测试。`verify-ui-emulator.py` 已适配新的列表和聊天页导航，可以在准备好的环境中继续执行。

接下来的交互检查应覆盖会话列表与返回操作、两个会话之间的草稿保存、未读数量及其清除、搜索和筛选、深浅色与大字体、原有主题色和新默认色，以及群发失败后的重试。未读记录只保存在界面配置中，通信协议和长期密钥文件没有变化。
