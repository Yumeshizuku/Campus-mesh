# 0.3 Telegram 风格界面更新

0.3 版本把聊天整理成更接近 Telegram 的使用方式：先在列表里找到会话，再进入独立聊天页。应用继续使用 Campus Mesh 的名称和公钥身份，外观设置、草稿和离线通信功能也都保留。

## 从会话列表开始聊天

首页会显示圆形首字头像、最近一条消息、时间、本机未读数量和草稿提示，常用会话优先排列。没有联系人时，页面会说明怎样添加同学。头像颜色会根据身份或会话标识保持一致，当前使用首字头像。

Android 可以按“全部”“私聊”和“群发”筛选会话，也能通过右下角按钮新建会话。进入聊天页后，底部页签会收起，顶部显示头像和名称，搜索与会话设置放进菜单。返回后可以继续浏览会话列表。

新安装默认使用蓝色主题，已经设置过的主题、字号和深浅色偏好会继续生效。Android 增加了蓝色工具栏和抽屉导航入口，iOS 使用原生导航栏。

## 消息和输入区的变化

消息改成带方向的圆角气泡，日期、时间和发送状态重新排布。默认蓝色主题在浅色模式下使用白色接收气泡、浅绿发送气泡和淡灰绿背景；深色模式使用深蓝色背景与气泡。选择其他主题色时，浅色模式中的发送气泡会跟随调整。

发送按钮换上了圆形纸飞机图标，快捷短语可以从输入区菜单选择。原有的草稿保存、外观自定义、常用群发和部分提交失败后的重试功能继续保留。

## 未读和送达状态是什么意思

未读数字表示这台设备上还没有查看的消息。进入会话后，已有消息会记为已查看，这些记录只保存在本机，不会额外向对方发送已读回执。

“已送达”表示通信核心已经验证了对方的端到端回执。“等待送达”和“已过期”也根据核心返回的实际状态显示。这个版本没有加入在线时间、通话、文件附件或云同步。

## 构建和运行进展

早期 Android 0.3.0 / versionCode 3 已完成 ARM64 APK 构建和代码检查，当时记录为 0 个错误、9 个警告。签名和 16 KB 对齐检查也已完成。随后发布的 Android alpha-0.3.0 使用内部版本号 4，下载与后续修复见[发布说明](releases/alpha-0.3.0.md)。

这一阶段最初只完成了七个 iOS Swift 文件的语法解析，没有把它记为完整构建。后续 iOS alpha-0.4.0 已通过 Xcode 编译，并在 iOS 26.2 模拟器上完成基础页面操作、昵称修改、通信启停与设置重启保存检查，实际截图也已保存。最新进展见[验证报告](VERIFICATION.md)，iOS 后续外观变化见 [Liquid Glass 更新](LIQUID-GLASS.md)。

早期 Android 软件模拟器没有完成冷启动，因此没有得到 Android 界面操作或运行截图的通过记录。后续仍需在正常模拟器或手机上检查会话返回、不同会话的草稿、未读清除、搜索与筛选、深浅色和大字体，以及群发失败后的重试。已有的 `scripts/verify-ui-emulator.py` 可以在准备好的环境中继续执行。

早期原始记录保存在 `reports/telegram-android-build.txt`、`reports/telegram-android-lint.txt`、`reports/telegram-apk-signature.txt`、`reports/telegram-apk-alignment.txt` 和 `reports/telegram-swift-syntax.txt`，各自对应当时的检查阶段。
