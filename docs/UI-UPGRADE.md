# 0.2 界面更新

0.2 版本围绕日常聊天和个性化设置做了调整，让切换会话、保存草稿和联系多位好友更方便。这份说明保留了当时的功能记录；后续的聊天布局见 [Telegram 风格更新](TELEGRAM-STYLE.md)，最新编译与操作结果见[验证报告](VERIFICATION.md)。

## 聊天和常用操作

应用分成聊天、附近、身份和自定义四个页面。连接设备、交换公钥和调整外观各有入口，私聊与群发也分别保存在独立会话中。消息使用左右气泡区分，发送状态用中文显示；会话内的搜索最多展示最近 200 条匹配消息。

每个会话都会自动保存本机草稿，切换页面或重新打开应用后可以接着写。常用好友和会话可以置顶，常用群发成员也能保存下来。长按消息可以复制内容，快捷短语选中后会先填入输入框，再由你确认发送。短语最多保存 8 条，每条最多 80 个字符。

群发仍然为每位收件人分别加密。如果只有部分成员的消息提交失败，保持文字不变再次发送，会只重试尚未提交的成员。修改成员后，旧的重试名单会清除。消息是否真正送达，仍需要通信核心确认对方的端到端回执；当前群发功能不包含管理员或自动同步成员名单。

## 按自己的习惯调整外观

深浅色可以跟随系统，也可以固定为浅色或深色。应用提供四种主题色，以及 14、16、18、20 四档聊天字号，还可以切换紧凑气泡和时间显示。

“恢复默认外观”会重置主题、颜色、字号、密度和时间设置，同时保留身份、聊天记录、草稿、快捷短语和常用群发。主题与偏好只保存在本机。

## Android 和 iOS 的使用方式

在当时的 Android 界面中，可以通过顶部选择器切换好友或常用群发，并从会话旁的菜单设置常用好友、编辑成员。输入区与消息列表分开，搜索或刷新消息时会保留输入框。“附近”页面集中提供扫码、粘贴公钥、蓝牙、局域网连接和系统 Wi-Fi Direct 配对入口。后续 0.3 版本已把聊天首页改成会话列表。

iOS 可以在聊天首页搜索会话，向右轻扫设置常用好友。进入会话后，可以搜索消息、保存草稿和编辑群发成员。输入区会随键盘调整位置；阅读旧消息时收到新消息，会出现“最新消息”按钮，由你决定何时回到列表底部。

两个平台都会适应明暗模式。Android 使用适合屏幕密度和系统字体的尺寸，主要按钮至少有 48 dp 的触控高度；iOS 发送按钮至少提供 44 pt 的触控区域，聊天字号也会随系统动态字体缩放。Android 外观配置和 iOS 偏好分别保存在各自的本机应用配置中，升级会继续保留原有身份文件。

## 验证进展与复查步骤

0.2 阶段已完成 Android 构建和静态检查，但软件模拟器没有成功启动，因此当时没有完成界面操作验证。后续 iOS 已通过完整编译，并在 iOS 26.2 模拟器上验证了基础页面操作、昵称修改、通信启停，以及昵称与自定义设置的重启保存。历史结果见[界面验证记录](UI-VERIFICATION.md)，后续结果见[验证报告](VERIFICATION.md)。

继续复查时，可以按以下顺序操作：

1. 为两位好友分别输入草稿，切换会话和底部页面，确认内容没有串到另一位好友。
2. 重启应用，检查身份、公钥、草稿、外观、字号、短语和群发成员是否保留。
3. 在当前会话搜索关键词，再退出搜索，确认结果范围和原有草稿正确。
4. 阅读旧消息时接收新消息，检查滚动位置；发送成功后应清空输入框，提交失败时应保留文字。
5. 让群发中的一位成员提交失败，检查重试范围，以及“已排队”和“已送达”的显示。
6. 使用深色、最大字号和紧凑模式，检查长中文、多行消息、横屏、键盘和辅助功能，再恢复默认外观，确认身份与聊天数据完整。

蓝牙、Wi-Fi Direct 和手机局域网通信仍需要真机验证。界面检查的具体覆盖范围以对应报告为准。
