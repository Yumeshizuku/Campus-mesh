# alpha-0.6.0：路由与可靠性

## 路由怎样工作

BLE 为每条 GATT 中心或外设链路分配临时本地名称。收到的封装通过签名、时间和消息 ID 校验后，才会学习发送设备经该链路可达的反向路径。重复封装也需要验签。评分为 `跳数 × 256 + RSSI 绝对值`，优先少跳，同跳数优先强信号，最多选取两条链路。未能测得 RSSI 的外设链路使用 -80 dBm；该数值不是实测结果。路径 60 秒没有有效观测便过期；连接断开会立即清理对应状态。

这是机会式反向路径学习，并非完整链路状态协议。网络尚未学到收件人路径时，会使用可用邻居进行受限扩散；消息创建 15 秒后仍未收到端到端回执时，也允许其他链路转发。两条 GATT 链路未必属于两台不同设备，更不代表全程节点互不重叠。局部信号变化与可变跳数不能作为安全证明，也不承诺全网最优路线。

每链路独立记录发送尝试，未到重试时间不重复提供同一封装。退避从 2 秒增长至最多 256 秒，并加入 0–2 秒的抖动，实际发送还取决于配置的同步频率及 GATT 进度。同一轮优先提供尝试次数较少的封装，随后优先本机控制/回执，再按创建时间排列。已收到同一封装的链路不会被立即回传。重试状态只保存在内存，重启会重新尝试；密文缓存、去重表、身份和历史继续原子保存。发送尝试表示已交给蓝牙队列，并不表示已经送达。

路由表最多 2048 项、24 条本地链路、8192 条已知来源记录；GATT 仍最多同时连接 4 台外设并接受 4 台中心订阅。缓存上限、TTL 和跳数仍受原有 Mesh 参数控制，最大分别为 4096 条、24 小时和 8 跳。中继只保存密文，目标离线时会继续携带，遇到新邻居或设备重新靠近后同步。TCP 保留 inventory 交换，只补发对方缺少的封装。

## 送达与已读

`queued` 显示为“发送中”，收件端解密并接收后产生加密的 `ack`，发送方显示 `delivered`。聊天页面在前台打开时，对收到的消息调用 `read`，生成加密的已读回执；发送方显示 `read`。回执与私聊目标或群消息原始收件成员绑定，其他好友不能代替目标确认。群消息只有全部目标成员均已读时，整体状态才变为已读。

已读回执先到也能确认送达，之后较晚的 ACK 不会降级状态。已读标记在本地保存，重复打开不会不停产生回执。回执本身也进入密文缓存并参与重试；超过消息有效期仍未返回时无法保证发送方最终看见状态。已读表示会话已经打开，不代表对方一定认真阅读了文字。接收方没有打开应用、后台限制或系统暂停蓝牙时，不会产生远程已读状态。

## 加密与兼容

新封装的 `version` 为 2，使用 AES-256-GCM 和随机 96 位 nonce；每条消息仍生成临时 X25519 密钥，通过原有 HKDF-SHA256 消息域派生加密密钥。私聊和群成员副本均独立加密，外层 Ed25519 签名覆盖版本、身份、公钥、有效期、跳数上限和密文。version 1 的 192 位 nonce 与 XChaCha20-Poly1305 封装仍可读取。收到消息不自动替换已信任好友的密钥，扫码应当核对对方身份。

BLE 的服务与数据 UUID 后缀改为 `BC1D0020`，避免旧版应用把新封装当作普通 JSON。参与同一蓝牙网络的手机需要一起升级；保留旧身份和沙盒文件即可继续使用已有好友与群。旧版 TCP 节点无法解密新 version 2 消息，也应升级。没有引入前向保密、硬件密钥托管或匿名路由。

## 分包与功耗

BLE 线上仍为四字节大端长度，随后是 `CM2` 三字节标记和 zlib 压缩后的加密 Frame JSON。压缩发生在加密之后，减少重复字段和十六进制表示的开销，不压缩聊天明文。FFI 使用 Base64 传递这些二进制数据，Base64 本身不进入 GATT。接收端对线上数据和解压结果都限制为 65536 字节，分包缓冲含长度头最多 65540 字节；中断超过 30 秒的未完成缓冲丢弃。签名在解压后验证。

Android 请求 ATT MTU 247，两端使用协商后的可用写入/通知长度，上限 244 字节，未协商时回退 20 字节。写入仍等待 GATT 确认；通知发送也保留系统流控。连接中断后重建通道，依靠核心重试重新提供完整封装。

两端每轮扫描约 10 秒，有连接时暂停约 20 秒，孤立时暂停约 5 秒。同步间隔从设置值开始，连续空闲时逐步增长，最长 60 秒，有数据发送后恢复。Android 在无连接时使用平衡广播模式，有连接后使用低功耗模式；iOS 的广播间隔和发射功率由系统管理，应用仅调度扫描与同步。以上为调度目标，系统节流和后台政策仍会改变实际行为。

## 验证范围

`cargo test --workspace --locked` 覆盖旧测试与新增的压缩/篡改、受限解压、每链路退避、多路转发、跳数/RSSI 排序、断路恢复、超时扩散、来源去重、乱序 ACK/已读、群成员回执绑定，以及离线中继重启后漫游同步。另有旧加密格式解密与伪造已读拒绝测试。运行 `cargo clippy --workspace --all-targets --locked -- -D warnings`、四进程真实 TCP 验证与 10/30/100/300 节点仿真。

平台构建及模拟器操作由本分支 GitHub Actions 检查；构建通过也不能替代手机验证。仍需至少两台 Android 和一台 iPhone 测试短/长中文消息、20/244 字节分包、通知拥塞、分片途中断线、弱信号、节点移动、回执丢失和熄屏恢复。实际吞吐量、送达率、功耗收益与多跳无线容量尚未测量。
